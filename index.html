02 / LEVEL ONE

🧱 CREATE IT — Your first website

Estimated time: 30–60 minutes. We use Termux, a free terminal app for Android, so you build like a real developer. Start simple; improve it as you learn.

STEP 1.1 · THE BASICSXP +100

So, what is a website?

A website is a collection of pages and files that a browser can show to people over the internet. HTML gives it structure, CSS styles it, and JavaScript can make it interactive.

Think of HTML as the building, CSS as the paint and layout, and JavaScript as the switches and moving parts.
STEP 1.2 · INSTALL TERMUXAndroid · free

Set up your phone as a dev studio

Termux is a free terminal app for Android. Install it from F-Droid or the official GitHub releases page, which the Termux project recommends. Open it, let the first-time setup finish, then run these commands one by one.

⌨️ Termux · one-time setup
pkg update && pkg upgrade -y
termux-setup-storage
pkg install nano python -y
mkdir mysite
cd mysite
  • pkg update && pkg upgrade -y refreshes Termux's software list and updates it.
  • termux-setup-storage asks Android for storage permission. Tap Allow.
  • pkg install nano python -y installs a text editor (nano) and Python (for previewing).
  • mkdir mysite creates a folder and cd mysite moves you into it.
If pkg update fails or is very slow, run termux-change-repo and pick a different mirror. Using an iPhone? Termux is Android-only, so use any code editor app and follow the same file steps.
STEP 1.3 · CREATE YOUR FILESCopy → Paste → Save

File one: index.html

This is the main page. In Termux (inside your mysite folder) run nano index.html, tap Copy code below, then long-press in Termux and choose Paste. Save with CTRL+O then Enter, and exit with CTRL+X. (Tap CTRL in the extra keys row above your keyboard, then the letter.) Using a code editor app instead? Just create the file and paste.

📄 index.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="description" content="My first website, built entirely on my phone.">
  <title>My First Website</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <main class="hero">
    <p class="tag">MY FIRST WEBSITE</p>
    <h1>Hello, internet! 👋</h1>
    <p>I built this website using only my phone.</p>
    <a class="button" href="#about">Explore my site</a>
  </main>
  <section id="about">
    <h2>A little about me</h2>
    <p>I'm learning to build things for the web.</p>
  </section>
</body>
</html>

File two: style.css

This file controls the colours, spacing, and appearance. Run nano style.css and paste it the same way.

🎨 style.css
* { box-sizing: border-box; }
body {
  margin: 0;
  font-family: Arial, sans-serif;
  background: #101827;
  color: #f5f7fb;
  text-align: center;
}
.hero { padding: 70px 20px; }
.tag { color: #00ff88; letter-spacing: 2px; }
h1 { font-size: clamp(2rem, 8vw, 4rem); }
p { color: #b9c5d3; line-height: 1.7; }
.button {
  display: inline-block;
  margin-top: 15px;
  padding: 12px 20px;
  background: #00ff88;
  color: #06140d;
  border-radius: 8px;
  text-decoration: none;
  font-weight: bold;
}
section { padding: 35px 20px; }

STEP 1.4 · PREVIEW ITSee it before the world does

Run your site on your own phone

Still inside mysite, start a tiny local web server:

⌨️ Termux
python -m http.server 8080
  1. Leave Termux running, open Chrome, and visit http://localhost:8080.
  2. You should see your styled page. If it looks plain, check the file is named exactly style.css.
  3. Go back to Termux and press CTRL+C to stop the server.
Edit with nano, save, refresh Chrome. That is the whole build loop. If Android closes Termux when you switch apps, pull down the Termux notification and tap Acquire wakelock.
STEP 1.5 · GET READY TO UPLOADTermux → phone storage

Copy your files where your browser can reach them

Hosting sites let you upload files from your phone's storage, but Termux keeps its files in a private folder. From inside mysite, copy them out:

⌨️ Termux
mkdir -p ~/storage/shared/mysite
cp index.html style.css ~/storage/shared/mysite/

Now when a website asks you to choose files, look in Internal storage → mysite. Run the cp command again whenever you edit your files.

03 / LEVEL TWO

🚀 HOST IT FREE — Put it online

Hosting stores your website files on a server so other people can visit them. The services below offer free options, subject to their current limits and terms.

Don't overthink it: pick ONE. We recommend GitHub Pages because it is the most reliable on a phone. Options B and C are alternatives for later.
OPTION A · GITHUB PAGES · ⭐ RECOMMENDEDBest starting point on a phone

Publish with GitHub Pages

  1. Create or sign in to a GitHub account in your phone browser.
  2. Create a new public repository, for example my-first-website.
  3. Tap Add file → Upload files, choose index.html and style.css from the mysite folder in your phone's storage (Step 1.5), then commit to the main branch.
  4. Open repository Settings → Pages. Under Build and deployment, choose deploy from a branch, then select main and /(root).
  5. Save and wait a few minutes for GitHub to publish your site. Open the Pages URL shown in settings. It looks like yourname.github.io/my-first-website/.

OPTION B · NETLIFYQuick deploy workflow

Publish with Netlify

  1. Open Netlify in your phone browser and create/sign in to an account.
  2. Connecting the GitHub repository from Option A is usually easier on a phone than drag-and-drop uploads.
  3. Upload your website folder containing both files, or select the connected repository.
  4. Wait for the deploy to finish, then open the generated site URL.
  5. Use the site settings to change the project name if that option is available.
📱 Screenshot placeholderNetlify dashboard → Add new site / Deploy
The exact dashboard layout may change over time.
OPTION C · VERCELGit-based deployment

Publish with Vercel

  1. Sign in to Vercel, preferably using the Git provider where your files are stored.
  2. Choose Add New → Project and import your website repository.
  3. For a plain HTML/CSS site, you usually do not need a framework or build command.
  4. Keep the project root set to the folder containing index.html, then deploy.
  5. Open the generated domain and test it on your phone.

04 / LEVEL THREE

🔎 GET IT ON GOOGLE — Help people find you

Google decides what to show in search. These basics help it understand your pages, but indexing and ranking are not guaranteed or instant.

Step 3.1 — Set up Search Console

  1. Open Google Search Console and sign in with your Google account.
  2. Add your website as a property. For a beginner, the URL-prefix option can be easier to verify.
  3. Follow the verification method shown. Depending on your hosting setup, an HTML file or an HTML meta tag may be available.
  4. Once verified, use URL Inspection to request indexing for your homepage.
📱 Screenshot placeholderSearch Console → Add property → Verify ownership

Step 3.2 — Create a sitemap

A sitemap is a file that lists important pages on your site. For a one-page website, you can start with this simple sitemap.xml and replace the example URL with your real public URL.

🗺️ sitemap.xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/</loc>
  </url>
</urlset>

Upload sitemap.xml to your site's root folder, then submit its path (usually /sitemap.xml) in the Sitemaps section of Search Console.

Only submit a sitemap that is actually published and accessible at your domain. A sitemap helps discovery; it does not force Google to index a page.

Step 3.3 — Add robots.txt (optional)

A robots.txt file tells search crawlers which parts of your site they may visit and where your sitemap is. Create it with nano robots.txt like your other files.

🤖 robots.txt
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
robots.txt only works at the root of a domain (like https://yourname.github.io/robots.txt). If your site lives at a subfolder URL such as yourname.github.io/my-first-website/, crawlers ignore it, so you can skip this until you have a custom domain. It is also not a way to hide private pages.

Step 3.4 — Write useful page metadata

  • Title: a clear, unique page title that describes the page.
  • Description: a short, accurate summary that may be used as a search snippet.
  • Keywords: use relevant words naturally in your content. The old meta keywords tag is not used by Google for ranking.
  • Social preview: add Open Graph tags (og:title, og:description, og:image) so your link looks good when shared on WhatsApp and social media.
  • Content: make the page genuinely useful, readable, mobile-friendly, and easy to navigate.
